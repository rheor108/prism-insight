# 2026-10-06 재현 오류 복구

## 확인된 원인과 수정

- ResearchPacket은 16개 제한 때문에 실제 매크로 결과 17개를 거부했습니다.
  수집 상한을 64개로 명시하고 검토는 최대 16개씩 순차 진행합니다.
  항목을 잘라내지 않으며 실패한 검토 묶음은 UNVERIFIED로 유지합니다.
- Claude OAuth 갱신 중단 메시지가 일반 인증 실패로 즉시 종료됐습니다.
  해당 잠금 충돌 메시지만 60초 뒤 한 번 재시도하며 기존 총 시간 제한을 유지합니다.
  실제 인증 만료, 로그아웃, 사용량 제한은 자동 재시도하지 않습니다.
  코드가 인증 잠금 파일이나 토큰을 삭제하지 않습니다.
- 구조화 평가의 도구 요청 분기에 빈 문자열 const를 사용하면 실제 CLI가
  `{"answer": , ...}`처럼 값을 누락해 내부 구조화 재시도를 소진하는 현상을
  가상 도구 요청으로 재현했습니다. 이 분기를 null로 바꾸고 검증 후 내부
  인터페이스에 맞게 빈 문자열로 변환합니다. 최종 답은 여전히 평가 객체여야 하며
  도구 요청과 최종 답을 섞으면 거부합니다. 원문 오류 응답은 운영 로그에 남기지 않습니다.
- KRX 인증 페이지 이동은 networkidle 대신 domcontentloaded를 기다립니다.
  이후 기존 로그인 iframe/입력 요소 대기를 유지합니다. HTTP 400 이상과 응답 없음은
  인증 미확인으로 중단하고 기존 재시도 억제를 유지합니다. 403을 성공으로 간주하거나
  인증을 우회하지 않습니다.

## 검증

- 17개/64개 수집, 16개 단위 검토, 일부 검토 실패 후 나머지 보존, 65개 거부.
- 일시적 OAuth 갱신 충돌의 성공/반복 실패, 실제 인증 오류 분리.
- null 도구 요청 → 부모 도구 실행 → 최종 객체 검증의 전체 경로.
- HTTP 403/응답 없음 거부, 기존 KRX 인증 예외와 브라우저 정리.
- 실제 Claude Sonnet 5 medium 가상 시험: 일반 평가 7.12초 성공,
  가짜 get_stock_ohlcv 1회 실행 후 평가 11.06초 성공.
  실제 계좌·운영 보고서·주문은 사용하지 않았고 운영 품질 표본에서 제외했습니다.

## 운영 적용과 한계

검증된 PR을 main에 병합한 후 운영 checkout을 ff-only 갱신하고 다음을 실행합니다.

```bash
.venv/bin/python tools/install_krx_auth_diagnostics.py
.venv/bin/python tools/install_krx_auth_diagnostics.py --check
```

패치 설치는 알려진 의존성 해시만 허용하며 원본 백업을 보존합니다.
실제 OAuth 복구에서는 실행 중인 Claude가 없고 50분 이상 갱신되지 않은
빈 잠금 디렉터리만 수동 정리했고 이후 가상 호출이 성공했습니다.
자동 잠금 삭제는 구현하지 않았습니다. 재발 시 동일한 상태 확인이 필요합니다.

KRX 공개 페이지 시험은 HTTP 403이므로 실제 인증 및 다음 운영 배치 정상화는
아직 확인되지 않았습니다. 모델/effort/매매 규칙/cron은 변경하지 않았습니다.
