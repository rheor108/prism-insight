# Codex 호출 실패 진단과 재시도

2026-09-10 적용. 구독 CLI 연결 계층에만 적용하며 모델, 매매 규칙,
MCP 권한 및 API fallback 금지 정책은 유지합니다.

- `[CODEX_FAILURE]`: 단계, 모델, 호출 식별자, 시도 번호, 종료 코드,
  오류 분류, 재시도 여부를 기록합니다. 메시지는 미리 정의한 설명입니다.
- `[CODEX_RECOVERED]`: 재시도 성공을 기록합니다.
- CLI JSON `turn.failed`/`error`를 우선 분석하고 없으면 stderr의 ERROR
  행을 분석합니다. 일반 모델 답변, 도구 결과, plugin WARN은 제외합니다.
- 원문 메시지, 프롬프트, 계정 정보는 로그에 넣지 않습니다. 알 수 없는 오류는
  `unknown`으로 남으며 원문을 복원할 수 없습니다. 이전 실패 원인도 소급 확정하지 않습니다.
- 원본 stdout/stderr는 권한 0600 임시 파일로 받아 마지막 256 KiB씩만
  분류합니다. 호출 종료 시 파일을 닫고 영구 진단 파일은 생성하지 않습니다.
- 확인된 연결 중단과 일시 서버 오류만 2초, 5초 간격으로 최대 두 번 재시도합니다.
  인증·사용량·rate limit·요청/모델/컨텍스트·응답 형식·알 수 없는 오류는
  이 계층에서 재시도하지 않습니다. 상위 기존 시나리오 재시도는 유지됩니다.
- 재시도는 CLI 한 번의 추론 요청만 반복합니다. 부모 MCP 도구 실행이나 주문을
  재실행하지 않습니다. research의 읽기 전용 웹 검색은 반복될 수 있습니다.
- 모든 재시도와 대기는 원래 호출 제한 안에 포함됩니다. 단계 전체의 기존
  시간제한과 배치 전체 제한도 유지합니다. timeout/cancel 시 자식 프로세스를 종료합니다.
- 이미 실행 중인 Python 배치는 기존 모듈을 사용합니다. 다음 새 배치부터 적용됩니다.

검증: `pytest -q tests/test_codex_failure_recovery.py tests/test_subscription_models.py`
