# 배치 시작 시 실제 매입원가 보정

국내·미국 추적 배치는 계좌별 `update_holdings()` 시작 시 한투 잔고와 매수 체결
내역을 읽고, 그 결과를 반영한 뒤 매도 판단과 수익률 계산을 진행합니다.
별도 WebSocket 수신 서비스나 추가 cron은 필요하지 않습니다.

예를 들어 분석 가격이 100이고 실제 2주 체결금액이 220이면, 분석 가격 100을
보존하고 실제 평균 매입가 110을 기록합니다. 현재가가 121일 때 수익률은
`(121 - 110) / 110 × 100 = 10%`입니다. 주문 접수 응답의 가격이나 주문 전
시세는 체결 증거로 사용하지 않습니다.

## 저장 필드

`stock_holdings`, `us_stock_holdings`, `trading_history`, `us_trading_history`에
다음 필드를 추가합니다. 기존 필드·행·ID·회고는 삭제하지 않습니다.

| 필드 | 의미 |
|---|---|
| `analysis_price` | 최초 분석 가격. 보정 시 변경하지 않음 |
| `actual_buy_price` | 확인된 평균 매입가 |
| `actual_buy_quantity` | 원가를 확인한 수량 |
| `actual_buy_amount` | 해당 수량의 매입원가. 국내 KRW, 미국 USD |
| `entry_cost_status` | `UNVERIFIED`, `PARTIAL`, `CONFIRMED` |
| `entry_cost_source` | 분석 대기, 과거 미확인, 잔고, 주문 체결 중 근거 종류 |
| `entry_cost_checked_at` | 조회 근거 시각(UTC) |

호환성을 위해 `buy_price`도 확인된 실제 평균 매입가로 보정합니다. 따라서 기존
수익률·매도 판단·회고 전달 경로도 보정된 가격을 사용합니다. 매도 기록 직전에는
DB 잠금 안에서 최신 원가를 다시 읽으므로 오래된 호출 인자의 분석 가격을 사용하지 않습니다.
새 매도 이력은 정확히 대응하는 보유 행의 분석 가격·실제 원가·근거를 함께 보존합니다.
보정 전후 값과 주문 참조는 `entry_cost_reconciliations`에 남기며, 동일한 조회를
다시 적용해도 금액을 누적하거나 같은 변경 이력을 반복 생성하지 않습니다.

기존 기록의 `analysis_price`는 이전 `buy_price`에서 가져옵니다. 과거에 이미 수동
보정됐다면 최초 분석 가격을 자동 복원할 수 없으므로 별도 근거로 이전해야 합니다.
기존 종료 거래의 수익률을 재계산하거나 기존 가격을 실제 체결가로 인증하지 않습니다.

## 주문과 잔고의 연결

- 새 주문은 계좌·시장·종목·주문번호·주문일 및 `source_position_id`로 연결합니다.
  가격이 같다는 이유로 주문을 연결하지 않습니다.
- 국내 예약번호는 예약조회 응답으로 일반 주문번호에 연결합니다. 미국 예약 및
  로컬 `PENDING-*` 주문도 계좌가 일치하는 명시적 큐/예약 참조를 따라갑니다.
- 독립된 추가 매수 행이 여러 개라면 각 행에 연결된 체결금액/수량을 사용하고,
  합계 수량과 평균 원가가 증권사 잔고에 맞는지 대조합니다. 추가 매수 판단에 사용하는
  평균 매입가도 확인된 수량으로 가중 평균합니다.
- 주문 참조가 없는 기존 단일 보유 행은 현재 증권사 잔고의 평균 매입가·수량으로
  보정할 수 있습니다(`broker_balance`). 이때 금액은 현재 잔여 보유분의 매입원가이며,
  과거에 매도한 수량까지 포함한 최초 총 매수금액을 복원한 것은 아닙니다.
- 여러 기존 행에 계좌 전체 평균가를 임의로 나눠 넣지 않습니다. 주문번호 매칭 실패,
  수량 불일치, 부분 체결은 확인 대상으로 남깁니다. 최근 주문 조회 범위는 최대 90일입니다.

## 미확인 상태와 실행 범위

미확인/부분 체결 종목 또는 조회상 수량 불일치 종목은 해당 배치의 매도 판단을 보류합니다.
확인된 평균 원가가 없는 종목은 수익률 기반 추가 매수도 통과하지 못합니다. 요약에는
미확인 원가의 수익률을 숫자로 표시하지 않습니다. API 장애 시 기존 확인 원가를
분석 가격으로 덮어쓰지 않으며, 잔고가 없다고 보유 기록을 자동 삭제하지도 않습니다.

보정 시점은 다음 배치입니다. 주문 방식(시장가/종가/예약), 매수 예산, 프롬프트,
목표가·손절가 설정, 실제 매도 주문의 체결 확인 방식은 이번 변경 범위에 포함하지 않습니다.
수익률은 현재가 또는 기존 매도 기록 가격을 분자로 하고 실제 매입원가를 분모로 하는
가격 수익률입니다. 매도 체결가·수수료·세금·환율을 모두 반영한 순수익률로 바꾸는 기능은 아닙니다.

## 검증과 복구

```bash
python -m pytest tests/test_entry_cost_reconciliation.py -q
```

테스트는 네트워크 없이 국내/미국, 실제 원가/분석 가격 차이, 부분 체결 증가,
수량 가중 평균, 잘못된 계좌/주문/날짜, 예약·로컬 큐, 페이지 누락, 반복 적용,
매도 이력 보존, 조회 실패를 검증합니다. 운영 전에는 SQLite backup API로 복사본을
만들고 해당 계좌의 읽기 전용 조회 결과로 복사본을 확인해야 합니다.
코드 rollback 시 추가 컬럼은 남겨도 됩니다. 이미 보정한 `buy_price`는 실제 원가이므로
분석 가격으로 되돌리지 않습니다. DB 전체를 과거 사본으로 덮어써 새 거래를 잃으면 안 됩니다.
