# 외부 검색 근거 검토

Codex `research` 단계의 일반 텍스트 검색은 근거 수집과 원문 대조를 순서대로 실행합니다. 기존 `perplexity-ask` 대체 경로에도 적용됩니다. 모델과 effort, API 전환 정책 및 매매 규칙은 바꾸지 않습니다.

## 처리 흐름

1. 수집 호출은 질의의 기준일과 보도일 범위를 식별하고 요청한 항목을 구조화합니다. 공식 기관·회사 IR·뉴스룸을 우선하며, 실적 질문에서는 사업부 표/PDF도 확인하도록 지시합니다. 검색 스니펫만으로 원문을 읽었다고 처리하지 않습니다.
2. 각 항목에는 주장, 상태, 수치·단위·기간, URL·발표일·짧은 근거를 붙입니다. 자료를 못 찾았거나 접근에 실패한 상황과 공식 비공개를 분리합니다. 하나의 출처에서 못 찾았다는 이유로 비공개라고 판단하지 않습니다.
3. 같은 설정의 두 번째 모델 호출이 후보 근거를 신뢰하지 않고 원문을 다시 열어 대조합니다. 요청 항목의 ID를 유지하며 잘못된 수치·기간·확정 표현을 수정하고 누락 항목만 추가 조사합니다.
4. Python 검사는 항목 누락/중복, URL 형식, 열람 표시, 출처 날짜 범위, 수치의 근거 발췌 내 존재, 단위·기간 유무를 검사합니다. 공식 비공개 표기가 없는 `NOT_DISCLOSED`는 `NOT_FOUND`로 낮춥니다. 검토가 끝나지 않은 초안은 확인된 사실로 내보내지 않습니다.
5. 최종 문자열은 검토된 주장과 항목별 URL·날짜로 생성합니다. 번호 인용과 URL 목록을 별도로 만들지 않아 번호 연결 오류를 피합니다. 근거 발췌 원문은 최종 답변에 재게시하지 않습니다.

## 상태의 의미

| 상태 | 의미 |
|---|---|
| SUPPORTED | 출처에 근거가 있는 주장. 전망·분석·미확인 보도는 별도 표시하며 회사 확정 사실로 승격하지 않음 |
| NOT_FOUND | 이번 검색에서 확인하지 못함. 비공개라는 뜻이 아님 |
| ACCESS_FAILED | 원문 접근 실패로 확인 불가 |
| NOT_DISCLOSED | 열람한 공식 자료가 해당 정보의 비공개/미공시를 명시한다고 검토됨 |
| CONFLICTED | 출처 간 불일치를 해결하지 못함 |
| UNVERIFIED | 원문 대조 또는 구조 검증을 통과하지 못함 |

## 운영 범위와 제한

- 두 호출은 순차 실행하며 기존 research 단계의 전체 제한 시간을 공유합니다. 반복 검색을 줄이도록 지시하지만 검색 도구 호출 수 자체를 강제로 제한하거나 응답 시간이 줄어든다고 보장하지 않습니다.
- 리뷰가 전송 오류·잘못된 응답·항목 불일치로 실패하면 초안 내용을 숨기고 해당 항목들을 `UNVERIFIED`로 반환합니다. 취소와 전체 시간 초과는 상위 호출로 전달합니다. 수집 단계 자체 실패도 그대로 전달합니다.
- `response_model`이 지정된 저수준 구조화 호출은 이 파이프라인 내부에서 사용하며 중복 검토하지 않습니다. 매수·매도 등 다른 단계에 검토 호출을 직접 추가하지 않습니다.
- 이는 **같은 모델의 별도 호출을 통한 원문 대조와 구조 검사**입니다. 독립 공급자 검증, 원문 발췌의 암호학적 증명, 의미·단위 변환의 완전한 자동 증명이 아닙니다. 모델이 출처 내용이나 열람 상태를 잘못 보고할 가능성은 남습니다.
- 공식 기관 분류, 질의에서 추출한 기준일, 주장의 의미는 모델 검토에 의존합니다. 날짜를 모르는 자료는 기간 제한 질의의 확인 근거로 사용할 수 없습니다.
- 영구 캐시와 Perplexity 자동 보조 호출은 추가하지 않았습니다. 캐시 만료 정책이나 비용·장애 전환은 별도 평가가 필요합니다.
- 코드 변경은 외부 정보의 수집·검토 단계에 한정됩니다. 선별/진입/청산/수량 규칙, 임계값, 주문 및 자동 전략 승격은 변경하지 않습니다.

검증은 `tests/test_research_quality.py`와 기존 구독·도구 프로토콜 테스트로 수행합니다. 라이브 재비교 결과는 같은 날짜의 비교 보고서에 추가합니다. 운영 설정을 되돌릴 경우 공개 `run_stage`의 research 전용 래퍼를 이전 단일 호출로 복구하는 작은 코드 되돌리기로 한정합니다.
