# KRX 인증 실패 진단

2026-09-09: `kospi-kosdaq-stock-server 0.4.2`의 KRX 직접 로그인 경로에
진단 정보를 추가했습니다. 아래 2026-09-10 보강에서 인증 실패 재시도 정책을
조정했습니다. 매매 점수·진입/매도 조건·예산은 바꾸지 않습니다.

## 설치와 확인

저장소 루트에서 운영 Python으로 실행합니다.

```bash
.venv/bin/python tools/install_krx_auth_diagnostics.py
.venv/bin/python tools/install_krx_auth_diagnostics.py --check
```

설치 도구는 원본 SHA-256과 패치 내용을 검증하고 해당 인터프리터의
`krx_data_client.py`에 적용합니다. 원본은 같은 디렉터리의
`krx_data_client.py.prism-original`에 보존합니다. 다른 소스 버전이면 변경 없이
중단합니다. 가상환경 재생성 또는 의존성 재설치 후에는 위 명령을 다시 실행해야 합니다.
이미 패치된 상태에서 재실행해도 중복 적용하지 않습니다.

현재 운영 cron과 kospi_kosdaq MCP는 같은 `.venv` Python을 사용합니다.
새 프로세스부터 적용되며 이미 import한 프로세스에는 소급 반영되지 않습니다.
다른 Python/uvx 환경을 쓰는 배포에서는 그 환경도 별도로 설치·확인해야 합니다.

## 기록되는 정보

- `[KRX_AUTH_DIAGNOSTIC]`: 로그인 시도 ID, PID, 경과 시간, 실패 단계.
- KRX 문서/XHR/fetch 응답의 경로, HTTP 상태, 메서드, Content-Type.
- 크기가 명시된 16KB 이하 JSON 응답의 message/error/code/result 계열 필드만 추출.
  HTML 원문·큰 응답·크기 미상 응답은 읽지 않고 생략 이유를 기록합니다.
- 로그인 제출 직후와 실패 시점의 본문 안내 문구, iframe 안내 문구, 팝업 메시지.
  오류·차단·인증 등의 문구를 우선 기록합니다. 최대 3개 프레임과 로그인 제출/팝업
  20건·후속 요청 20건을 별도로 보관합니다. 화면 캡처는 최대 2초,
  진행 중 응답 수집 대기는 최대 1초입니다.
- `[KRX_SESSION_VALIDATION]`: 세션 검증에서 HTML/HTTP 오류가 반환된 경우 상태·경로.

계정 ID/비밀번호 및 현재 쿠키 값은 마스킹에만 사용합니다. 요청 본문,
Authorization/Set-Cookie 헤더, URL 쿼리, HTML 원문, 입력 필드 값, 스크린샷은
기록하지 않습니다. 기존 라이브러리의 JavaScript 쿠키 값 로그도 제거합니다.
문구에 포함된 이메일·긴 식별자·전화번호 등은 추가로 가립니다.

홈 페이지 진입만으로 “로그인 성공”을 확정하던 메시지를 “데이터 인증 미검증”으로
바꿨습니다. 로그인 페이지로 돌아왔을 때 “다른 프로세스가 로그인했다”는 추정도
제거했습니다. 응답/안내 문구가 원인을 명시하지 않으면 원인은 계속 미확정입니다.

## 검증

```bash
.venv/bin/python -m pytest tests/test_krx_auth_diagnostics.py -q
```

실제 설치 소스에 패치를 적용한 로그인 함수를 가짜 브라우저로 실행하여,
인증 실패 예외는 유지하면서 브라우저 정리 전에 증거를 남기는지 확인합니다.
민감값 마스킹, 이벤트/응답 크기 제한, 캡처 실패, 알 수 없는 의존성 거부를 검사합니다.
이 검증은 외부 로그인이나 주문을 실행하지 않습니다.

## 2026-09-10 장애 후속 보강

- 종료된 Playwright 연결에서 이벤트를 제거하다 발생한 오류를 무시하고, 로그 필터를
  항상 제거합니다. 원래 인증 실패 예외가 정리 오류에 가려지지 않습니다.
- URL의 쿼리는 제거하되 경로와 로그 식별자는 유지합니다. 로그인 제출 증거는
  홈 화면의 후속 요청이 많아져도 별도의 버퍼에 보존됩니다.
- 세션 검증 HTTP 400/403/500 등은 인증 만료로 단정하지 않고 세션 파일을 보존합니다.
  데이터 요청의 HTTP 오류도 세션 만료 예외로 변환하지 않습니다. 명시적 JSON
  `RESULT=LOGOUT`의 기존 만료 처리와 확인된 접근 차단의 기존 24시간 정책은 유지합니다.
- 로그인 실패 또는 세션 검증 HTTP 오류 후 계정별 300초 재로그인 휴지기를 적용합니다.
  `.krx_auth_retry_<계정해시>.json`에 실패 시각만 기록하며, 같은 사용자의 MCP/배치
  프로세스가 공유합니다. 실패 중 요청이 들어와도 휴지기를 다시 연장하지 않습니다.
  5분 후 다시 시도할 수 있고 성공하면 상태를 지웁니다.
- 현재가 조회가 KRXAuthError로 실패하면 기존 KIS → 계좌별 DB 대체 경로로 즉시
  전환합니다. 일시적 네트워크 오류의 기존 재시도는 유지합니다.
- kospi_kosdaq MCP 제한은 45초에서 180초로 조정했습니다. AI 단계 40분과 전체
  배치 120분 제한은 유지합니다. KIS 현재가 및 아카이브 자료 보강은 설정된 계좌 모드를
  사용하며 `auto_trading=False`로 초기화합니다.

이는 KRX 서버의 인증/접근 문제를 해제하는 변경이 아닙니다. 대체 데이터가 없는
수급 항목 등은 계속 조회 불가일 수 있으며, 없는 데이터를 만들어 제공하지 않습니다.


## 2026-09-11 HTTP 400 LOGOUT 복구

저장 세션으로 HTTP/HTTPS를 각각 조회한 결과 모두 상태 400, 본문 `LOGOUT`
(6바이트)이 확인됐습니다. 이전 패치는 상태 코드만 보고 예외를 발생시켜
명시적인 세션 만료 신호를 놓쳤습니다.

- 검증 응답이 정확히 HTTP 400 + 본문 LOGOUT이면 만료로 처리하고 로그인 락
  안에서 다른 프로세스의 최신 세션을 먼저 재확인한 뒤 재로그인을 허용합니다.
- 단순 HTML 400, 401/403/429/500은 기존처럼 인증 만료로 단정하지 않습니다.
- 로그인 실패 시 계정별 300초 휴지기 및 확인된 접근 차단 정책을 유지합니다.
- 실제 데이터 요청의 일반 HTTP 400 처리와 매매 규칙은 변경하지 않습니다.
- 비밀번호 변경이나 다른 계정 로그인 때문에 세션이 만료됐는지는 이 응답만으로
  알 수 없습니다. 새 로그인 후 데이터 접근 성공 여부는 별도 검증해야 합니다.

운영 검증: 수정된 경로의 로그인 성공 후 저장 세션을 새 인스턴스로 불러오자
HTTP/HTTPS 데이터 요청 모두 200으로 복구됐습니다. 로그인 함수 반환 직후의
기존 인스턴스 검증은 한 차례 LOGOUT이었으므로, 로그인 메시지만으로 성공을
판정하지 않고 새 저장 세션으로 실제 데이터 조회를 확인했습니다.

추가 확인: 정상 조회 역시 Content-Type이 text/html이지만 본문은 JSON입니다.
따라서 헤더만으로 만료 판정을 내리는 기존 로직도 제거하고 실제 JSON 본문을
파싱합니다. 실제 HTML 로그인 화면/비 JSON 응답은 계속 실패 처리합니다.
최종 수정 후 새 인스턴스의 `_validate_session()`이 True를 반환했고,
실제 자료 조회에서 output 915행을 확인했습니다. 관련 테스트 30개 통과.
